# 3. 행위 패턴 (Behavioral Patterns)

행위 패턴은 **객체들 간의 상호작용과 책임 분배**에 중점을 둔 디자인 패턴입니다.  
객체들이 서로 협력하면서 발생하는 복잡한 제어 흐름을 효율적으로 관리하고, 객체 간의 결합도를 낮추는 다양한 방법을 제공합니다.

### 왜 사용하는가?

여러 객체가 긴밀하게 얽혀있어 변경이 어렵거나, 객체의 역할과 책임이 불분명할 때 유용합니다.  
행위 패턴을 적용하면 객체 간의 통신 방식을 표준화하고 알고리즘을 캡슐화하여 코드의 유연성과 유지보수성을 크게 향상시킬 수 있습니다.

### 이 카테고리의 패턴들

* **책임 연쇄 패턴 (Chain of Responsibility Pattern):** 요청이 해결될 때까지 여러 객체를 체인처럼 따라가며 처리 기회를 줍니다.
* **커맨드 패턴 (Command Pattern):** 요청 자체를 객체로 캡슐화하여 다양한 방식으로 활용합니다.
* **이터레이터 패턴 (Iterator Pattern):** 컬렉션의 내부 구조를 노출하지 않고 요소들에 순차적으로 접근합니다.
* **미디에이터 패턴 (Mediator Pattern):** 여러 객체 간의 복잡한 상호작용을 중재자 객체 하나에 집중시킵니다.
* **메멘토 패턴 (Memento Pattern):** 객체의 내부 상태를 저장했다가 이전 상태로 복원할 수 있게 합니다.
* **옵서버 패턴 (Observer Pattern):** 한 객체의 상태가 변하면 의존하는 다른 객체들에게 자동으로 알림을 보냅니다.
* **상태 패턴 (State Pattern):** 객체의 내부 상태에 따라 행동을 변경하게 합니다.
* **전략 패턴 (Strategy Pattern):** 유사한 알고리즘들을 캡슐화하여 동적으로 교체할 수 있게 합니다.
* **템플릿 메서드 패턴 (Template Method Pattern):** 알고리즘의 골격은 상위 클래스에서 정의하고, 일부 단계는 하위 클래스에서 구현합니다.
* **비지터 패턴 (Visitor Pattern):** 기존 객체의 코드를 변경하지 않고 새로운 기능을 추가합니다.
