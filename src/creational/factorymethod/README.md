# 팩토리 메서드 패턴 (Factory Method Pattern)

### 1. 목적 (Intent)

객체를 생성하기 위한 인터페이스를 정의하되, 어떤 클래스의 인스턴스를 생성할지에 대한 결정은 서브클래스에서 내리도록 하는 생성 패턴입니다.  
이를 통해 클래스의 인스턴스화 로직을 서브클래스로 미룰 수 있습니다.

### 2. 문제 (Problem)

어떤 클래스가 자신이 생성해야 할 객체의 타입을 예측할 수 없을 때 문제가 발생합니다.  
특정 타입의 객체를 생성하는 코드가 기존 클래스에 직접 묶여있으면(tightly coupled), 새로운 타입을 추가할 때마다 기존 클래스를 수정해야만 합니다.  
이는 OCP(개방-폐쇄 원칙)를 위반하여 유연성을 떨어뜨립니다.

### 3. 해결 (Solution)

팩토리 메서드 패턴은 객체 생성 로직을 '팩토리 메서드'라는 별도의 메서드로 분리합니다.  
부모 클래스는 이 팩토리 메서드를 호출하여 객체를 생성하지만, 실제 어떤 객체가 생성될지는 이 메서드를 오버라이드(override)하는 서브클래스에 의해 결정됩니다.

이를 통해 부모 클래스는 구체적인 '제품(Product)' 클래스에 대한 의존성 없이, 오직 '제품' 인터페이스에만 의존하게 됩니다.

---

### 시나리오

주문 데이터를 다양한 형식(`CSV`, `PDF`)의 파일로 내보내는 기능을 구현합니다.

* **Before:** `ExportService` 클래스 내에 파일 형식에 따른 객체 생성 로직이 `if-else`로 복잡하게 얽혀있는 문제를 확인합니다.
* **After:** 팩토리 메서드 패턴을 적용하여, 새로운 파일 형식이 추가되어도 `ExportService`의 수정 없이 기능을 유연하게 확장할 수 있는 구조로 리팩토링합니다.
