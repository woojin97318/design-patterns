# 싱글턴 패턴 (Singleton Pattern)

### 1. 목적 (Intent)

**클래스의 인스턴스가 오직 하나만 생성되도록 보장하고, 그 인스턴스에 대한 전역적인 접근 지점(Global Access Point)을 제공**하는 생성 패턴입니다.

### 2. 문제 (Problem)

애플리케이션 전체에서 단 하나만 존재해야 하는 객체가 필요한 경우가 있습니다. 예를 들어, 시스템의 환경 설정을 관리하는 객체, 데이터베이스 커넥션 풀, 또는 로깅 객체 등이 그렇습니다. 만약 이런 객체들이 여러 개 생성된다면, 상태가 일치하지 않거나 불필요한 리소스가 낭비되는 심각한 문제가 발생할 수 있습니다.

### 3. 해결 (Solution)

싱글턴 패턴은 다음과 같은 방법으로 이 문제를 해결합니다.

* **생성자를 private으로 선언**하여 외부에서 `new` 키워드(혹은 Kotlin의 생성자 호출)로 인스턴스를 생성하는 것을 막습니다.
* 클래스 내부에 **자기 자신의 유일한 인스턴스를 저장할 정적(static) 변수**를 만듭니다.
* 외부에서 유일한 인스턴스에 접근할 수 있도록 **정적(static) 메서드**(보통 `getInstance()`)를 제공합니다. 이 메서드는 인스턴스가 아직 없으면 생성하고, 이미 있다면 기존 인스턴스를 반환합니다.



---

### 시나리오

애플리케이션 전체에서 단 하나의 데이터베이스 커넥터를 관리하는 `DatabaseConnector`를 구현합니다.

* **Phase 1:** Java에서 사용하던 고전적인 방식(Double-checked locking)으로 구현하여 패턴의 원리를 이해합니다.
* **Phase 2:** Kotlin의 `object` 키워드를 사용하여 코틀린스러운 방식으로 리팩토링합니다.
