# 2. 구조 패턴 (Structural Patterns)

구조 패턴은 **클래스와 객체들을 조합하여 더 큰 구조를 만드는 방법**을 다루는 디자인 패턴입니다.  
개별적으로는 독립적인 클래스들이 함께 작동하며 더 새롭고 강력한 기능을 제공할 수 있도록 유연한 구조를 설계하는 데 중점을 둡니다.

### 왜 사용하는가?

클래스나 객체의 구조가 복잡해지거나, 기존 코드를 수정하지 않고 기능을 확장해야 할 때 유용합니다.  
구조 패턴을 사용하면 시스템의 구조를 유연하고 효율적으로 만들면서도, 구성 요소 간의 결합도를 낮출 수 있습니다.

### 이 카테고리의 패턴들

* **어댑터 패턴 (Adapter Pattern):** 호환되지 않는 인터페이스를 가진 클래스들을 함께 동작하도록 변환합니다.
* **브리지 패턴 (Bridge Pattern):** 추상화와 구현을 분리하여 각각 독립적으로 확장할 수 있게 합니다.
* **컴포지트 패턴 (Composite Pattern):** 개별 객체와 복합 객체를 동일하게 다룰 수 있는 트리 구조를 만듭니다.
* **데코레이터 패턴 (Decorator Pattern):** 기존 객체를 감싸 동적으로 새로운 책임을 추가합니다.
* **퍼사드 패턴 (Facade Pattern):** 복잡한 서브시스템에 대한 단순화된 단일 인터페이스를 제공합니다.
* **플라이웨이트 패턴 (Flyweight Pattern):** 다수의 작은 객체들을 공유하여 메모리 사용량을 줄입니다.
* **프록시 패턴 (Proxy Pattern):** 특정 객체에 대한 접근을 제어하기 위해 대리자(Proxy)를 제공합니다.
