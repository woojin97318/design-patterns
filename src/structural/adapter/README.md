# 어댑터 패턴 (Adapter Pattern)

### 1. 목적 (Intent)

한 클래스의 인터페이스를 클라이언트에서 사용하고자 하는 다른 인터페이스로 변환합니다.  
어댑터를 이용하면 인터페이스 호환성 문제 때문에 같이 쓸 수 없었던 클래스들을 연결해서 쓸 수 있습니다.

### 2. 문제 (Problem)

기존에 잘 사용하던 클래스나 시스템을 새로운 시스템에 통합해야 할 때, 인터페이스(메서드 시그니처 등)가 맞지 않아 직접 연결할 수 없는 경우가 많습니다.  
그렇다고 해서 기존 시스템의 코드를 수정하는 것은 위험하거나 불가능할 수 있습니다.

### 3. 해결 (Solution)

어댑터 클래스를 만들어 중간에 끼워 넣습니다.

* 어댑터는 클라이언트가 기대하는 인터페이스(Target Interface)를 구현(implements)합니다.
* 어댑터는 내부에 연결해야 할 기존 클래스(Adaptee)의 인스턴스를 가집니다.
* 클라이언트가 어댑터의 메서드를 호출하면, 어댑터는 내부의 기존 클래스 인스턴스가 이해할 수 있는 방식으로 요청을 변환하여 전달합니다.

---

### 시나리오

우리 시스템의 표준 로그인 방식인 `UserLogin` 인터페이스와, 외부 라이브러리 또는 레거시 시스템인 `LegacyAuth` 클래스가 있습니다.  
`LegacyAuth`의 코드를 수정하지 않고, 우리 시스템에서 로그인을 처리하도록 어댑터를 구현합니다.

* **Before:** `UserLogin` 인터페이스와 `LegacyAuth` 클래스의 메서드 시그니처가 달라 직접 연결할 수 없는 상황을 확인합니다.
* **After:** 어댑터 패턴을 적용하여 `LegacyAuth`를 `UserLogin` 인터페이스에 맞춰 변환하고, 클라이언트 코드의 변경 없이 시스템에 통합합니다.
